1. NHỮNG GÌ TÔI TỰ XÁC MINH (KHỚP)
======================================================================

A. Thumbnail + nén ảnh — media-service.ts:
   - MAX_EDGE=2000, WEBP_QUALITY=82, THUMB_MAX_EDGE=400, THUMB_WEBP_QUALITY=70.
     ĐÚNG y báo cáo (dòng 36-39).
   - GIF: không nằm trong COMPRESSIBLE → giữ nguyên bytes, không mất ảnh động. ĐÚNG.
   - WebP đã ≤2000px: return nguyên buffer, KHÔNG encode lại vô ích (dòng 119-121). ĐÚNG.
   - Asset dedup thiếu thumbnail: tự vá khi gặp lại (dòng 275-281). ĐÚNG.
   - Có log [media][perf] stage=storage_write đo thumbnailMs. ĐÚNG.

B. Schema — schema.prisma:
   - MediaAsset.thumbnailUrl (@map thumbnail_url) CÓ THẬT (dòng 3995).
   - Các cột index migration cần (kind, last_used_at, archived_at, created_at, org_id)
     đều tồn tại trên model. Migration hợp lệ.

C. Upload trình duyệt — frontend/src/api/media.ts:
   - Timeout mỗi tệp = 5*60_000 (5 phút). ĐÚNG.
   - Tối đa 3 upload đồng thời: if (active.size >= 3) await Promise.race(active). ĐÚNG.
   - Partial-success: trả { assets, failed }; 1 ảnh lỗi KHÔNG hủy cả batch;
     chỉ throw khi TẤT CẢ lỗi. ĐÚNG (dòng 122-127).
   - Giữ tên gốc qua originalFilenames. ĐÚNG.

D. Bảo mật SSRF — chat-media-helpers.ts:
   - assertSafeRemoteUrl: chặn protocol lạ, chặn user:pass trong URL, chặn localhost/.local,
     resolve DNS rồi loại private/loopback/link-local/metadata IP. ĐÚNG.
   - fetchRemoteMediaBuffer: redirect manual, tối đa 3 chặng, timeout 30s, byte cap. ĐÚNG.
   - assertUserProvidedMediaUrlAllowed: host phải thuộc LOCAL_PUBLIC_URL / S3_PUBLIC_URL /
     MEDIA_REMOTE_HOST_ALLOWLIST, có hỗ trợ wildcard *.domain. ĐÚNG.
   - Guard áp cho MỌI đường tải media (kể cả send-block). Baseline vững.

     4. Chạy DRY-RUN: npm run media:backfill-thumbnails (KHÔNG --apply).
     5. Đọc số scanned/failed. Sạch mới chạy: -- --apply.
     6. Thử tài khoản test: mở kho, upload 10-20 ảnh, gửi 1 ảnh + 1 album.
     7. Theo dõi log [media][perf] + Server-Timing.
