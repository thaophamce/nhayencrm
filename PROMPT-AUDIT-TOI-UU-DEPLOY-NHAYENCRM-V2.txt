## 4. Điểm yếu cần đặc biệt sửa trong kế hoạch cũ

### 4.1 Backup chưa đủ

Kế hoạch cũ chỉ dump PostgreSQL bằng:

```powershell
docker exec zalo-crm-db pg_dump -U crmuser zalocrm > backup-truoc-deploy-2026-07-26.sql
```

Không mặc định dùng cách này trên Windows PowerShell vì redirection có thể gây vấn đề encoding và không kiểm chứng restore. Hãy thiết kế backup an toàn gồm:

- PostgreSQL custom format;
- kiểm tra backup bằng `pg_restore --list`;
- lưu checksum SHA-256;
- backup volume/file local vì `STORAGE_DRIVER=local`;
- backup `.env` theo cách bảo mật, không đưa vào repo/báo cáo;
- backup compose/config Cloudflare Tunnel;
- ghi dung lượng, thời gian, nơi lưu;
- thử restore vào DB/container test riêng nếu tài nguyên cho phép;
- không dùng production DB làm nơi thử restore.

Mẫu an toàn cần xem xét:

```powershell
docker exec zalo-crm-db pg_dump -Fc -U crmuser -d zalocrm -f /tmp/nhayencrm-predeploy.dump
docker cp zalo-crm-db:/tmp/nhayencrm-predeploy.dump .\backups\nhayencrm-predeploy.dump
docker exec zalo-crm-db pg_restore --list /tmp/nhayencrm-predeploy.dump
Get-FileHash .\backups\nhayencrm-predeploy.dump -Algorithm SHA256
```

Đây chỉ là mẫu. Phải xác minh container name, DB user/name và quyền trước. Không tự chạy nếu chưa được duyệt.

### 4.2 Phải backup media local

DB backup không chứa file trong `/var/lib/zalo-crm/files`. Xác định chính xác named volume/bind mount và tạo quy trình backup read-only. Không dùng chuỗi lệnh xóa/move. Có checklist restore DB + media cùng mốc thời gian.

### 4.3 Public port app và MinIO

Cloudflare Tunnel không yêu cầu app lắng nghe `0.0.0.0`. Xác minh có thể bind app production về:

```text
127.0.0.1:3080:3000
```

Nếu tunnel chạy trên host Windows. Kiểm tra Docker Desktop networking trước khi chốt. Tương tự MinIO:

- nếu không dùng: cân nhắc profile/stop sau xác minh dependency;
- nếu vẫn cần admin/internal: bind loopback;
- thay compose phải recreate đúng service;
- kiểm tra Windows Firewall và router port-forward, không chỉ Docker bind.

Không khẳng định “MinIO hở internet” chỉ vì bind `0.0.0.0`; phải kiểm tra firewall/NAT. Nhưng vẫn đánh dấu bind rộng là exposure risk.

### 4.4 Named Tunnel trên Windows

Phải phân biệt hai cách:

- tunnel quản lý bằng token từ dashboard;
- locally-managed tunnel dùng credential JSON + `config.yml`.

Xác minh cách dùng trước khi đưa lệnh. Kế hoạch phải ghi:

- nơi lưu credential/config;
- quyền NTFS;
- Windows service account;
- service startup/recovery;
- log path và log rotation;
- kiểm tra service sau reboot;
- cách uninstall/rollback service;
- không ghi tunnel token vào repo hoặc command history nếu tránh được.

Kiểm tra DNS apex đã có A/AAAA/CNAME hay record xung đột. Không tự ghi đè DNS.

### 4.5 Cloudflare và cache

Đưa checklist:

- SSL/TLS mode phù hợp với Tunnel;
- Always Use HTTPS;
- `www` redirect nếu chọn;
- không cache `/api/*` và `/socket.io/*`;
- cân nhắc cache `/files/*` chỉ khi nội dung immutable và không chứa private media;
- WebSocket được phép;
- upload/body size và timeout;
- WAF/rate limit cho login/public endpoints;
- không bật Cloudflare Access trước app nếu Zalo webhook/CDN/public media cần truy cập;
- kiểm tra IPv6/DNS propagation;
- kiểm tra origin chỉ vào được qua loopback/tunnel nếu mục tiêu là private origin.

### 4.6 Public `/files` và quyền riêng tư

Kế hoạch cũ coi public `/files` là lợi ích nhưng chưa audit privacy. Kiểm tra:

- URL có đủ entropy không;
- có đoán được tên file không;
- có directory traversal/listing không;
- có file nhạy cảm không;
- response có `X-Content-Type-Options: nosniff` không;
- MIME đúng không;
- cache-control có phù hợp không;
- xóa media có thật sự ngừng truy cập không;
- có cần signed URL hay authorization không;
- Zalo CDN cần public URL tới mức nào.

Nếu media khách hàng nhạy cảm, nêu rõ tradeoff local public static so với signed URL/R2 private. Không tự đổi kiến trúc storage trong cùng deployment nếu chưa duyệt.

### 4.7 Không xóa 8 DB records trực tiếp

Tạo quy trình:

1. Query xác định record.
2. Kiểm tra foreign keys/references đến message/media/content/thumbnail.
3. Export record ra JSON/CSV để rollback.
4. Backup DB.
5. Cleanup trong transaction.
6. Kiểm tra row count chính xác.
7. Commit hoặc rollback.

Cleanup phải là task riêng sau deploy ổn định, không nằm trên critical path đưa domain lên production.

### 4.8 Không gộp theme refactor với deploy

Kế hoạch cũ ghi theme thay quá phạm vi. Audit diff:

- `frontend/src/assets/hs-crm-theme.css`
- `frontend/src/plugins/vuetify.ts`
- layout/chat widths/radius/font/message width/shadows

Phân loại:

- branding thuần;
- behavior/layout change;
- accessibility/responsive regression.

Không tự revert vì workspace có thay đổi người khác. Đưa thành quyết định riêng, không chặn domain nếu build và smoke test đạt, trừ khi gây lỗi UI thực tế.

## 7. Security audit bắt buộc

### Auth/session

- access/refresh token rotation và revoke;
- force password change;
- login/setup rate limit;
- secret strength nhưng không in giá trị;
- CORS exact origins cho apex và quyết định với `www`;
- CSRF nếu dùng cookie;
- Secure/HttpOnly/SameSite nếu có cookie;
- logout và session Zalo không bị ảnh hưởng ngoài dự kiến.

### RBAC/tenant isolation

- mọi DB query scope `orgId`;
- mọi Zalo operation kiểm tra account access;
- Socket.IO room theo org/user;
- public API key đúng tenant;
- IDOR trên `/:id`;
- raw SQL có tenant condition;
- report/export/batch route không rò tenant.

### Input/media/webhook

- SSRF;
- path traversal;
- upload MIME/size;
- XSS/rich text;
- CSV formula injection;
- HMAC constant-time + replay protection;
- webhook retry/idempotency;
- Telegram/Pancake/Zalo secrets backend-only;
- log redaction.

### Lời mời kết bạn Zalo

Xác minh fix mới:

- popup web đọc live `getFriendRecommendations()`;
- chỉ lấy `recommType = 2`;
- không lấy suggestion `recommType = 1`;
- scope `[]` mở rộng thành tất cả nick có quyền;
- Đồng ý/Từ chối dùng đúng accountId và UID;
- route có ACL;
- không tạo request storm với nhiều nick;
- cần concurrency limit nếu số nick lớn;
- lỗi một nick không làm mất dữ liệu nick khác;
- danh sách web khớp Zalo điện thoại.

## 11. Kế hoạch deploy chuẩn cần viết lại

Tạo kế hoạch theo pha, mỗi pha có:

- người thực hiện;
- lệnh chính xác;
- điều kiện trước;
- kết quả mong đợi;
- cách xác minh;
- điểm dừng;
- rollback;
- mức gián đoạn dự kiến.

### Pha A — Preflight, không thay đổi hệ thống

- audit Git/build/test;
- Docker/container/port/env read-only;
- DNS/tunnel/service read-only;
- disk/memory/backup capacity;
- migration status;
- files/assets cần commit;
- chốt `GO/NO-GO`.

### Pha B — Backup và restore verification

- DB custom-format backup;
- media volume backup;
- config backup bảo mật;
- checksum;
- restore test riêng;
- ghi Recovery Point Objective và Recovery Time Objective thực tế.

### Pha C — Chuẩn bị Cloudflare trước cutover

- Named Tunnel/token hoặc config rõ ràng;
- service setup;
- DNS conflict check;
- hostname tới `http://localhost:3080`;
- chưa đổi app URL cho tới khi tunnel health đạt;
- kiểm tra bằng hostname tạm nếu có thể;

### Pha D — Cutover

- maintenance window;
- ghi thời điểm bắt đầu;
- cập nhật chính xác `APP_URL` và `CRM_LOGIN_URL`;

- không đổi secret;
- kiểm tra container env đã nhận giá trị mới;
- kiểm tra health trước mở traffic.

### Pha E — Smoke test

Tối thiểu:

5. Socket.IO/WSS realtime.

10. 92 ảnh R2 cũ.

13. Telegram/Pancake/webhook nếu production dùng.
14. PWA install/update.
15. Mobile.
16. CORS từ domain thật.
17. Không còn request đến IP LAN/localhost/5173.

### Pha F — Hardening sau ổn định

Không gộp vào cutover nếu không cần:

### Pha G — Theo dõi 24 giờ và 7 ngày

## 12. Rollback phải cụ thể

Kế hoạch rollback cần phân tầng:

### Rollback domain/config

- phục hồi `.env` cũ từ bản backup bảo mật;
- recreate app;
- kiểm tra IP/LAN access cũ nếu còn cần;
- rollback DNS/tunnel route;
- không đổi secret.

### Rollback container/image

- lưu image digest/tag trước deploy;
- deploy lại image cũ;
- không build đè tag duy nhất;
- kiểm tra schema compatibility.

### Rollback DB

- chỉ restore khi có thay đổi DB gây lỗi và được phê duyệt;
- restore DB có thể làm mất dữ liệu phát sinh sau backup, phải cảnh báo rõ;
- ưu tiên rollback app nếu schema backward-compatible;
- media và DB phải đồng bộ mốc.

### Rollback Cloudflare service

- stop/disable service mới;
- khôi phục quick tunnel chỉ nếu thật sự cần và biết URL thay đổi;
- gỡ DNS route đúng cách;
- không xóa tunnel/credential trước khi hệ thống ổn định.

Đặt tiêu chí rollback tự động/manual, ví dụ:

- login fail liên tục;
- 5xx vượt ngưỡng;
- Socket.IO không kết nối;
- media gửi Zalo lỗi;
- DB migration lỗi;
- tenant/security issue;
- healthcheck không đạt sau thời gian giới hạn.

---

## 13. Tiêu chí NO-GO

Đánh dấu `NO-GO` nếu còn một trong các điều kiện:

- backend/frontend build fail;
- targeted test cho thay đổi mới fail;
- migration pending/không rõ;
- backup DB hoặc media chưa kiểm chứng;
- restore plan không có;
- secret/default credential yếu hoặc lộ;
- auth/RBAC/tenant isolation lỗi;
- production build phụ thuộc file untracked;
- DNS/tunnel config chưa rõ hoặc record xung đột;
- origin/app/DB/Redis/MinIO exposure không được hiểu rõ;
- Docker production không health;
- login/chat/realtime/media fail;
- public `/files` có path traversal hoặc lộ dữ liệu nghiêm trọng;
- không có rollback image/config;
- ổ đĩa không đủ;
- máy chủ không bảo đảm uptime tối thiểu mà chủ dự án yêu cầu.

`GO WITH CONDITIONS` chỉ dùng khi không có security/data-loss blocker và mọi điều kiện còn lại có owner + deadline rõ.

## 15. Cách làm việc

1. Bắt đầu bằng plan.
2. Đọc report cũ và trạng thái Git.
3. Kiểm tra read-only trước.
4. Báo sớm nếu có blocker bảo mật/mất dữ liệu.
5. Chỉ sửa blocker high-confidence, không sửa lan man.
6. Sau mỗi sửa, chạy targeted test và build.
7. Không dừng ở “build pass”; phải kiểm tra deploy/runtime plan.
8. Cuối cùng trả lời ngắn:
   - Verdict hiện tại?
   - Claim nào trong kế hoạch cũ sai/nguy hiểm?
   - Blocker nào còn?
   - File nào đã tạo/sửa?
   - Chủ dự án phải làm gì?
   - Khi nào mới được cutover?

Bắt đầu ngay bằng việc đọc `KE-HOACH-DEPLOY-NHAYENCRM.html`, `git status`, compose, Dockerfile, `.env.example`, cấu hình runtime và code liên quan. Không thực hiện deploy thật.
